## 交叉熵确实是一个数值。但 PyTorch 记住的不是这个数值，而是「这个数值是怎么算出来的」。

---

### 关键区分：值 vs 计算图

```python
loss = F.cross_entropy(logits, action)   # loss = 0.342（一个标量）
loss.backward()                          # 自动算出 ∂loss/∂W, ∂loss/∂b ...
```

`loss = 0.342` 这个数字本身确实没法求导。但 PyTorch 在算出 0.342 的**同时**，在后台偷偷记下了一整条计算链：

```
输入 s_t ──→ W,b ──→ logits ──→ softmax ──→ 取 action 对应的概率 ──→ -log() ──→ loss = 0.342
   ↑          ↑                                                                    ↑
  已知      需要求梯度                                                           最终标量
```

`.backward()` 做的事：**从 loss 这个标量出发，沿着这条链反向走回去**，用链式法则算出 loss 对每个中间变量的偏导，一直走到 $W$ 和 $b$。

---

### 用一个具体数值例子走一遍

假设极简网络：只有 2 个参数 $w_1, w_2$，输入 $x = 1$，输出 2 个动作的 logits：

$$
z_1 = w_1 \cdot 1, \quad z_2 = w_2 \cdot 1
$$

当前参数：$w_1 = 1.2,\; w_2 = 0.3$，采样动作 $a = 0$（第一个动作）。

#### 前向传播（PyTorch 边算边记）

```
① z_1 = w_1 = 1.2          ← 记住：∂z_1/∂w_1 = 1
② z_2 = w_2 = 0.3          ← 记住：∂z_2/∂w_2 = 1

③ softmax:
   p_1 = e^1.2 / (e^1.2 + e^0.3) = 3.320 / (3.320 + 1.350) = 0.711
   p_2 = e^0.3 / (e^1.2 + e^0.3) = 1.350 / (3.320 + 1.350) = 0.289
                            ← 记住：∂p_1/∂z_1 = p_1(1-p_1) = 0.711×0.289 = 0.205
                            ←        ∂p_1/∂z_2 = -p_1·p_2 = -0.711×0.289 = -0.205

④ 取采样动作 a=0 对应的概率：p_1 = 0.711

⑤ -log(p_1) = -log(0.711) = 0.342   ← 记住：∂(-log p)/∂p = -1/p = -1/0.711 = -1.406

loss = 0.342   ← 这就是你看到的"一个数值"
```

#### 反向传播（`.backward()` 做的事）

从 loss 出发，链式法则一路乘回去：

```
∂loss/∂p_1  = -1/p_1 = -1.406           （从⑤）
∂loss/∂z_1  = ∂loss/∂p_1 × ∂p_1/∂z_1 = -1.406 × 0.205 = -0.288
∂loss/∂z_2  = ∂loss/∂p_1 × ∂p_1/∂z_2 = -1.406 × (-0.205) = 0.288
∂loss/∂w_1  = ∂loss/∂z_1 × ∂z_1/∂w_1 = -0.288 × 1 = -0.288
∂loss/∂w_2  = ∂loss/∂z_2 × ∂z_2/∂w_2 =  0.288 × 1 =  0.288
```

**梯度出来了：**

$$
\nabla_w (\text{loss}) = [-0.288,\; 0.288]
$$

更新参数（学习率 $\eta = 0.01$）：

$$
\begin{aligned}
w_1 &\leftarrow 1.2 - 0.01 \times (-0.288) = 1.203 \quad &\text{（涨了 → 动作 0 更可能被选）} \\
w_2 &\leftarrow 0.3 - 0.01 \times 0.288 = 0.297 \quad &\text{（跌了 → 动作 1 更不可能被选）}
\end{aligned}
$$

### 如果乘上 $G_t$ 权重呢？

假设 $G_t = 50$（这步动作很好）：

```python
loss = -50 * log_prob   # = 50 × 0.342 = 17.1
loss.backward()
```

唯一的变化：链式法则的起点多了一个因子 50：

$$
\frac{\partial \,\text{loss}}{\partial w_1} = 50 \times (-0.288) = -14.4
$$

**梯度被放大了 50 倍**——好动作的 log 概率被大幅推高。这就是"加权"的数学实质。

---

### 一句话总结

> **交叉熵算出来是一个数值，但这个数值是 $W$ 的函数。PyTorch 在前向传播时悄悄记下了从 $W$ 到 loss 的每一步运算及其局部导数。`.backward()` 沿着这条链用链式法则把梯度反算出来。你看到的 0.342 只是函数的输出值，不是函数的全部——就像你知道 $f(3)=9$，但你还知道 $f(x)=x^2$，所以能算出 $f'(3)=6$。**
